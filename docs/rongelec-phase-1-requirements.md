# Rongelec 第一期官网需求规划

日期：2026-08-21
项目：南通睦融电气设备有限公司（MURONG）中英双语企业官网与单管理员后台

## 1. 文档用途

这份文档用于确定第一期要做什么、哪些页面面对客户、后台由谁维护以及如何验收。它是设计、开发和部署前的业务基线；技术实现细节以《[企业官网与内容后台设计方案](superpowers/specs/2026-08-19-rongelec-fullstack-website-design.md)》为准。

## 2. 当前项目分析

现有代码以 `test-last.html` 为主，是一套可展示品牌形象的静态单页网站，已经具备以下可迁移内容：

- 有声首页视频、声音开关、公司介绍、服务展示和服务网络。
- 三类既有服务：船舶自动化服务、岸电改造服务、配件供应。
- 关于我们、联系我们、在线服务申请、地点地图容器、页脚以及中英文切换文案。
- 隐私政策和服务条款独立页；现有 Logo、页脚、服务图片等素材。

当前缺口也很明确：页面通过前端脚本在单页内切换，不能被稳定收藏、分享或分别被搜索引擎收录；文字、图片、服务内容无法在后台修改；联系表单没有真正发送邮件；没有可持续发布的服务案例列表与详情页；现有中英文文本散落在页面脚本中，后续维护成本高。

第一期的目标不是在旧单页上继续堆功能，而是把已确认内容迁移为可管理、可跳转、可持续发布的官网。

## 3. 第一期开工范围

### 做什么

- 建设中文与英文两套公开页面，URL 固定、可直接分享和搜索。
- 建设一个管理员后台，用于编辑公司页面、服务、案例、媒体、SEO 与翻译术语。
- 新增“服务案例”持续发布能力：列表、详情、封面、相册、发布状态和分页。
- 后台所有可编辑文本采用富文本编辑器；管理员可编辑中文、创建空白英文，或一键生成英文初稿后人工校对。
- 访客提交服务申请后，服务端发送到指定 QQ 收件邮箱；不保存为后台客户线索。
- 适配从手机到宽桌面的合理屏幕尺寸；首页保留有声视频和声音开关。
- 部署在现有阿里云 Linux 2 核 4GB 服务器；图片与视频走阿里云 OSS/CDN。

### 第一明确不做

- 新闻动态、文章中心、用户注册、客户门户。
- 多管理员、角色、审批、工单、报价、派工、库存和 CRM。
- Excel/CSV 批量导入案例；案例按日常需要逐条维护。
- 联系表单的客户留言后台列表；邮件收件箱是唯一业务收件入口。
- 地图供应商选择或地图 API 配置；联系页只提供地点显示位置和容器，地图 API 由项目方后续接入。

## 4. 公开官网页面

所有公开页都有中文和英文版本。中文为默认语言，访问根路径 `/` 时固定进入 `/zh`；不根据浏览器语言自动跳转。英文内容尚未首次发布时，语言切换按钮置灰，英文地址返回 404，不跳回中文页面。

### 4.1 全站导航与页脚

主导航固定包含：首页、服务、服务案例、关于我们、联系我们、中英文切换。

页脚展示：公司名称、电话、服务邮箱、地址、快速链接、服务条款、隐私政策、ICP备案号及后续公安备案信息。所有这些文本都可在后台维护。

### 4.2 首页 `/zh` 与 `/en`

首页负责在最短时间内说明“睦融是谁、提供什么、如何联系”。页面包含：

- 现有风格的有声首屏视频、声音开关、主标题和行动按钮。
- 公司/品牌简介与核心价值。
- 三类服务入口，链接到对应服务详情。
- 精选服务案例入口；没有已发布案例时该区块不显示空内容。
- 服务网络、联系方式和咨询入口。

视频必须先显示轻量封面和文本，再按设备加载合适视频；手机使用 720p 版本，电脑使用 1080p 版本。访客第一次进入时按照浏览器规则静音播放，点击声音按钮后才开启声音。

### 4.3 服务列表与服务详情

服务列表页 `/zh/services`、`/en/services` 展示三类服务卡片及后续可增加的服务。

每项服务拥有独立详情页 `/zh/services/[slug]`、`/en/services/[slug]`，包含服务简介、适用场景、能力说明、配图和联系入口。当前三类既有服务内容从旧站迁移，后续由后台维护排序、封面和详情。

### 4.4 服务案例列表

案例列表是持续运营页面，路径为：

- 第一页：`/zh/cases`、`/en/cases`
- 后续页：`/zh/cases/page/2`、`/en/cases/page/2`

每页显示 12 条已发布案例，按发布时间倒序。案例卡片显示封面、标题、摘要、服务类型、船型标签和发布日期；点击进入详情。

第一期不增加前台筛选器，避免在案例数量尚少时增加维护和交互负担；服务分类与船型分类仍作为后台字段和前台标签保存，为后续筛选预留数据基础。

### 4.5 服务案例详情

案例详情路径为 `/zh/cases/[slug]`、`/en/cases/[slug]`。每个案例至少包含：标题、摘要、封面、服务/船型标签、项目背景、问题、解决方案、成果、正文图文和相册。

案例可被管理员设为首页推荐、发布或下架。下架、未发布或不存在的案例显示标准本地化 404 页面。发布后的 `slug` 默认锁定；确需修改时，旧地址保留 301 跳转。

### 4.6 关于我们

页面路径为 `/zh/about`、`/en/about`。迁移现有公司介绍、行业经验、团队优势、服务覆盖港口和服务网络表达。内容采用模块化区块，便于后续替换图片和补充公司信息，而不影响整体页面结构。

### 4.7 联系我们与服务申请

页面路径为 `/zh/contact`、`/en/contact`。展示公司名称、地址、电话、邮箱和地图位置；地图只要求在页面显示地点，具体地图 API 由项目方自行接入。

表单字段保持现有业务含义：姓名、公司名称、联系电话或邮箱、船舶信息、故障/服务描述。提交成功只表示邮件已经由 QQ SMTP 投递成功；发送失败时必须清楚提示电话和邮箱备用联系渠道。

### 4.8 法律页与系统页

- 隐私政策：`/zh/privacy`、`/en/privacy`
- 服务条款：`/zh/terms`、`/en/terms`
- 404 和 500：分别提供中英文文案、返回首页和联系入口。

## 5. 管理后台页面

后台只有一位管理员，没有角色或审批流。入口为 `/admin/login`；登录后所有管理页受到会话与 TOTP 二次验证保护。

### 5.1 后台概览

显示已发布/草稿的页面、服务、案例和媒体数量，以及需要处理的英文待复核内容和翻译失败任务。

### 5.2 页面内容管理

用于维护首页、关于、联系、页脚、隐私政策、服务条款及其他固定区块。每个内容提供：中文、英文、SEO、预览、发布分区。

编辑器支持标题、段落、加粗、斜体、列表、引用、对齐、链接、图片、表格、字体、字号和颜色。字体与颜色放在“更多格式”中；它们只用于局部强调，不允许破坏全站导航、页脚和响应式布局。

### 5.3 服务管理

用于维护服务排序、封面、中文/英文标题、摘要、正文和 SEO。首次公开发布需要确认中英文必填内容；之后中文和英文可以分别更新与发布。

### 5.4 案例管理

用于逐条新建、编辑、预览、发布、下架和排序案例。支持后台分页、基础筛选、封面、相册排序、服务分类、船型分类、首页推荐与稳定 `slug`。

### 5.5 媒体库

图片和视频上传到 OSS 后登记为媒体资产。后台校验文件类型、体积、像素和对象路径；公开媒体使用 CDN。原图不存入数据库，OSS Bucket 开启版本控制，以便误删或覆盖后恢复。

### 5.6 翻译、术语库与英文发布

中文编辑页底部提供三个明确操作：保存中文草稿、生成英文初稿、创建空白英文版。

“生成英文初稿”只生成英文草稿，不会直接发布，也不会覆盖已发布英文。系统冻结当前中文版本，将富文本按段落分块翻译，保留图片、链接、表格、船名、型号、IMO 编号等格式和不翻译内容。管理员在英文页签修改的内容只影响英文网站。

后台提供全局海事术语库。每个术语可设置中文、固定英文、备注和启用状态；系统只向 AI 注入当前内容命中的术语，生成后校验术语是否正确使用。

首次公开发布要求中文和英文均确认。后续中文更新会把英文标为“待复核”，但英文访客继续看到最后确认的英文版本；这保证官网不会出现半翻译页面。

### 5.7 网站设置与管理员恢复

网站设置管理公司信息、收件邮箱、默认 SEO 和术语库。QQ SMTP 授权码、DeepSeek API Key、OSS 凭据、地图 API Key、数据库密码等真实密钥只在服务器环境变量保存，不出现在后台输入框、Git 或浏览器代码中。

管理员启用 TOTP 时，系统一次性提供离线恢复码。若手机丢失，通过受限 SSH 服务器命令和独立重置令牌撤销旧 TOTP，再重新绑定；此路径不会依赖普通访客邮箱或公开网页。

## 6. 双语、内容与 SEO 规则

- 中文和英文分别保存草稿与已发布版本，均可人工编辑。
- DeepSeek-V4-Flash 仅用于生成国际海事英语、英式拼写的英文初稿；所有英文最终由管理员确认。
- 网站公开页必须具有本语言的标题、描述、Canonical、Open Graph 分享图和结构化数据。
- 中英文已发布对应页互相输出 `hreflang`，并输出指向中文首页的 `x-default`；Sitemap 只收录已发布语言版本。
- 搜索引擎禁止抓取后台和预览地址。

## 7. 响应式与性能要求

网站使用一套连续自适应布局，而不是分别开发手机、iPad、电脑三套页面。页面在 320px–2560px、横竖屏、长英文和 200% 缩放下不得出现整页横向滚动、文字截断或按钮遮挡。

首页关键图片和视频封面优先加载，其他图片懒加载；每张图片保留宽高信息避免跳动。中文 WebFont 限制 2–4 款，正文默认系统字体，标题字体进行子集化并由 OSS/CDN 缓存，避免字体下载拖慢移动端首屏。

移动端性能目标：LCP 不超过 2.5 秒、CLS 不超过 0.1、INP 不超过 200ms。首屏视频尚未下载完成时，标题、封面和主要联系按钮仍可立即使用。

## 8. 安全、邮件与上线边界

- 联系表单只发送到 QQ 收件邮箱，不保存客户正文到数据库。
- 表单设置必填/格式/长度校验、CR/LF 拒绝、蜜罐、最短填写时间和低于 SMTP 配额的 IP 限流。
- 管理员密码安全哈希、Cookie 安全属性、CSRF 防护、登录限流和 TOTP 必须具备。
- 公网 Git 不提交 `.env`、密钥、证书、数据库备份或真实账号；推送前与 CI 都进行敏感信息扫描。
- 每日加密备份数据库至独立 OSS 路径，保留 30 天；备份密钥离线保管并每月进行恢复验证。
- 生产服务器只开放 80/443；SSH 仅限管理来源；PostgreSQL 不开放公网端口。

## 9. 第一阶段验收清单

- 管理员可独立维护全部固定页面、服务、案例、图片和中英文内容。
- 中文和英文 URL 可直接访问、分享、收藏；英文未发布时不会展示空白英文页。
- 可以连续发布至少 100 条案例，列表分页、详情、封面和相册加载正常。
- 联系表单成功邮件可到达指定 QQ 邮箱；失败状态对访客可见。
- 首页保留有声视频和声音按钮，弱网或省流量环境至少保留封面与主要内容。
- 在 iPhone、主流 Android、iPad、Safari、Chrome、Edge，以及常见电脑宽度上完成关键流程测试。
- 翻译至少抽样 20 段真实或脱敏海事内容，由人工验收术语、英式拼写和海事语域。
- 服务器部署完成 HTTPS、OSS/CDN、数据库备份恢复演练、邮件发送、敏感信息扫描与旧站回滚准备。

## 10. 后续阶段候选项（不进入第一期）

- 案例前台按服务类型、船型、年份或港口筛选。
- 多管理员、审批和内容协作。
- 表单客户线索后台、报价或工单流转。
- 新闻动态、知识库和搜索能力。
- 访问统计仪表盘与营销自动化。
